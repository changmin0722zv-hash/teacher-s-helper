# 수업의 결 — 개인 수업 계획 도구

대한민국 초등학교 선생님을 위한 데스크톱 중심 수업 계획 웹앱입니다. 단원 계획을 먼저 세우고, 차시별 활동을 학반별 수업으로 구체화합니다. 여러 학년을 맡는 전담교사와 한 학급을 맡는 담임교사 모두 사용할 수 있습니다.

## 구현된 기능

- 학교·기초시간표: 부산광역시교육청·북부교육지원청 오션초등학교 등록, 요일·교시·학반·교과·적용 기간별 시간표 관리
- 선택한 주의 수업 일괄 등록: 미리보기에서 선택, 기존 등록 및 교시 겹침 제외, 행사·교시 미지정 기존 수업 안내, 한 번의 저장으로 반영
- 시간표 수업을 이동하거나 내용을 수정해도 독립적으로 보존. 같은 시간표 항목의 원래 날짜로 중복 등록 방지
- 나이스 학사일정: 인증키 연결 시 오늘 화면·달력에 대상 학년별 행사 표시. 기초시간표 미리보기에서는 행사일 기본 선택 제외

- 첫 화면 ‘오늘의 수업’: 한국 날짜 기준 수업, 자료 링크, 준비 체크, 같은 학반·교과의 직전 수업 메모를 모아 표시
- 빠른 기록은 기존 학생피드백 뒤에 추가하고, 수업 완료까지 한 번에 저장. 달력·보드·계획과 동일한 데이터를 사용
- 준비 체크는 수업별 저장. 상세 편집에서 미래·과거 수업의 체크 항목도 관리 가능
- 수업 계획: 교과, 날짜, 제목, 학년·학반, 남은 일 수, 준비상태, 학습목표, 교재, 활동, 학생피드백, 참고사항, 최초 기록 날짜
- 단원 지도 계획: 단원명, 학년·교과, 성취 수준, 차시별 활동, 기본설계, 비고
- 차시는 기본 6개이며 추가·삭제 가능. 연결된 수업이 있는 차시는 연결 해제 후 삭제
- 월간·주간 달력, 준비상태 보드, 수업·단원 목록과 상세 편집
- 달력 카드 우클릭 또는 ⋯ 메뉴로 수정·복사·삭제. 날짜 우클릭/⋯ 메뉴에서 붙여넣으면 날짜가 적용된 새 수업 편집 창을 열고 학반·교시를 확인한 뒤 저장
- 복사한 수업은 이 탭에 임시 보관하며 새로고침 시 초기화. 목표·활동·자료·출처는 보존하고 학생피드백·준비 체크·완료 상태는 초기화
- 달력에서 삭제 확인 후 마지막 삭제 한 건을 15초 동안 실행 취소. 다른 기록을 되돌리지 않고 해당 수업과 자료실 분류를 복원하며 동시 저장 충돌을 검사
- ⋯ 버튼은 터치·키보드로 사용 가능. 수업 카드에서 Shift+F10, 메뉴에서 방향키·Home·End·Enter·Escape 지원
- 교과·학년·학반 필터와 검색, 다른 학반으로 수업 복제, 전체 JSON 내려받기
- 상태: 계획 중 → 자료 준비 중 → 준비 완료 → 수업 완료
- 날짜는 Asia/Seoul 기준. 교시는 선택 사항이며 기초시간표로 등록한 수업에는 자동 지정
- 개인 GitHub 계정만 로그인 허용. 운영 기록은 연결된 Neon PostgreSQL에서 조회·저장
- 수업 자료실: 수업·단원의 모든 본문 검색, 날짜 없는 초안, 전 교과·학년군·라벨·성취기준 필터, 저장한 검색
- 교육과정 판본·영역과 활동·지원·운영 조건을 구분. 성취기준의 출처 검증과 교사 연결 여부를 각각 기록
- 참고 연결, 일부 내용 추가, 독립 초안·새 수업으로 재구성. 출처와 참조 당시 버전 보존
- 충돌 버전을 검사해 다른 기기 기록을 보호. 수업·단원 분류는 원문 편집 후에도 보존

성취 수준은 선생님이 자유롭게 입력합니다. 교육과정 문구를 자동 생성하거나 공식 성취기준을 내장하지 않습니다. 기본설계는 요청이 없으면 빈 문자열로 남습니다. 학생피드백은 학급 전체의 반응과 다음 수업 참고사항이며 학생별 기록을 수집하지 않습니다.

## 빠르게 개발하기

Node.js 24와 npm이 필요합니다.

```bash
npm ci
LOCAL_DEMO=true npm run dev
```

데모는 로그인 없이 화면을 개발·검증하는 모드입니다. 데이터는 무시되는 `.local/planner.json`에 저장되며 GitHub에 올라가지 않습니다. 개발 서버는 루프백 인터페이스에 바인딩합니다. 운영 빌드에서는 `LOCAL_DEMO=true`여도 데모 모드가 켜지지 않습니다.

```bash
npm run validate:data
npm test
npm run build
npm run typecheck
```

브라우저 테스트는 별도 개발 서버를 자동으로 실행합니다. 먼저 직접 실행한 개발 서버를 종료하세요.

```bash
npx playwright install chromium
npm run test:e2e
# 시스템 Chromium이 있으면 다운로드 없이 사용 가능:
CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

브라우저 테스트는 로컬 데모에 임시 데이터를 만들고 종료 시 기존 데이터를 복구합니다. 테스트 중에는 같은 데모를 직접 편집하지 마세요. GitHub의 실제 데이터에는 접근하지 않습니다.

## 학교·집에서 함께 쓰기

[배포 및 로그인 연결 안내](docs/DEPLOYMENT.md)를 따라 Private 저장소를 Vercel에 연결하고 GitHub OAuth App을 설정합니다. 현재 소스만으로 실제 사이트가 배포되거나 계정 연결이 완료되지는 않습니다.

Next.js 서버와 Neon PostgreSQL 연결이 필요합니다. GitHub는 코드 배포와 이전 원본 보관에 사용하며, DB 전환 후 일상적인 수업 저장은 재배포하지 않습니다. 저장 용량·복구 기간·요금 한도는 연결한 DB 요금제의 현재 안내를 확인하세요.

## Codex로 입력하기

같은 Private 저장소를 연결한 Codex에 다음처럼 요청합니다.

> 10월 21일 5학년 2반 영어 수업으로 ‘길 묻기 역할극’을 추가해줘. 준비상태는 자료 준비 중, 활동은 짝과 지도 보며 길 안내하기야. 클라우드에 저장해줘.

Codex는 `AGENTS.md`와 [데이터 규칙](docs/DATA.md)을 읽고 현재 저장 경로를 확인합니다. DB 전환 후에는 인증된 앱 API 또는 DB 연결이 안전하게 설정된 실행 환경에서 `cloud:records` 명령으로 최신 기록을 읽고, 버전 충돌 검사를 거쳐 저장합니다. 연결이 없는 채팅은 자동 저장할 수 없습니다. 이전 GitHub 백업을 수정해도 운영 DB에 반영되지 않습니다. 인증정보를 채팅에 붙여 넣지 마세요.

화면에서 저장 완료를 확인하면 다른 컴퓨터에서도 같은 DB 기록을 불러올 수 있습니다. 두 곳에서 동시에 수정하면 자동으로 덮어쓰지 않습니다. 새 자료와 분류는 자료실의 ‘자료 저장’을 눌러 보관합니다. 검색 조건을 저장하면 같은 조건의 자료가 계속 모이는 개인 책장처럼 이용할 수 있습니다.

오늘 화면의 준비 체크와 빠른 기록도 같은 방식으로 저장합니다. 저장하지 않은 빠른 기록은 내부 메뉴 이동과 ‘최신 내용 불러오기’ 동안 유지되지만, 브라우저를 닫으면 사라집니다. 충돌 시 최신 내용을 불러온 뒤 기록을 다시 저장할 수 있으며, 초안을 JSON으로 내려받을 수도 있습니다.

## 학교 일정 연결

학교 정보는 `data/school.json`에 등록되어 있습니다. 학교 코드 `7201223`, 시도교육청 코드 `C10`은 나이스 학교정보에서 확인했습니다. `NEIS_API_KEY`를 Vercel Production 환경변수에 설정하고 재배포하면 학교 일정을 조회합니다. 인증키를 채팅·저장소·브라우저 입력란에 넣지 않습니다. 키가 없어도 기초시간표와 주간 일괄 등록은 사용할 수 있습니다.

공개 행사는 브라우저에 연도별로 보관하고, 화면을 열 때 마지막 성공 조회에서 24시간이 지났으면 다시 확인합니다. 수동 새로고침도 가능합니다. 갱신 실패 시 같은 브라우저의 마지막 성공 자료를 유지하고 오류를 표시합니다. 학교 일정 조회는 수업 데이터나 GitHub 커밋을 변경하지 않습니다. 앱의 수정은 나이스로 전송되지 않습니다. 공지가 특정 반의 결강을 뜻하는지는 선생님이 판단합니다.

기초시간표는 등록할 주의 미리보기에서 수업을 선택한 후 실제 수업을 만듭니다. 항목 저장 자체는 수업을 생성하지 않습니다. 기초시간표 변경·삭제는 이미 생성한 수업을 바꾸지 않습니다. 수업을 삭제한 뒤에는 같은 주에서 다시 선택해 등록할 수 있습니다.

## 데이터와 제한

- 운영 데이터: Neon의 레코드·자료·분류·검색 조건. 변경된 자료의 버전과 최초 이전 원본도 DB에 보존합니다.
- `data/planner.json`에 `storageMigration`이 있으면 이전 당시 원본 백업입니다. 이후 운영 저장 대상이 아닙니다.
- 개발 데모: `.local/planner.json`. 실제 데이터와 분리됩니다.
- 첨부파일 업로드 대신 교재에 텍스트·링크를 적을 수 있습니다.
- DB에는 전체 900KB 제한이 없습니다. 자료실은 서버에서 검색하여 20개씩 조회합니다. 개별 자료 본문은 10만 자, 자료 저장 요청은 1MB, 수업 변경 요청은 3MB로 제한합니다.
- 달력·오늘 화면은 현재 전체 수업 기록을 나누어 불러옵니다. 수만 건 규모에서는 기간별 조회를 추가해야 하며, 무제한 성능을 보장하지 않습니다.
- 전체 JSON 내려받기는 수업·단원·시간표 대상입니다. 자료실의 선택 자료 내보내기는 분류·출처를 포함합니다. 전체 DB의 자료 버전·저장 검색까지 백업하려면 제공자의 DB 백업/내보내기를 사용해야 합니다.
- 오프라인 저장, 자동 병합, 알림, 인쇄 전용 화면, 학생별 기록은 첫 버전에 포함되지 않습니다.
- 공식 성취기준 사전 자동 수집, AI 라벨 추천, 의미 검색, PDF/HWP/OCR 본문 추출은 아직 포함되지 않습니다. 분류는 선택적으로 직접 입력하며 원문을 대조한 경우에만 확인 상태를 지정합니다.

## 구성

`app/`은 페이지와 인증·저장 API, `components/`는 화면, `lib/planner.ts`는 데이터 검증과 날짜 규칙, `lib/auth.ts`·`lib/security.ts`는 인증, `lib/storage.ts`는 저장을 담당합니다. 인증 정보는 서버에서만 사용하며 `NEXT_PUBLIC_` 환경 변수나 소스에 넣지 않습니다.

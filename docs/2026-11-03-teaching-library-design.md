# 수업의 결 — 교육과정 기반 자료실·검색·재사용 설계 v1.0

작성일: 2026-11-03 (Asia/Seoul)
상태: 단계별 설계 및 1차 구현 범위 기록. 공식 교육과정 자체가 아니라, 공식 자료를 참조하는 이 앱의 분류·운영 준칙이다.
범위: 초등학교 전 교과를 수용하는 분류 체계, 기존 기록 검색, 자료 축적과 선택적 재사용. 이 문서 작성으로 운영 데이터·앱·DB 연결을 변경하지 않는다.

## 1. 설계의 출발점

사용자는 달력을 중심으로 날짜별·학반별 수업을 유연하게 관리한다. 공통 수업안과 학반별 실행 기록을 의무적으로 나누거나, 모든 수업을 하나의 진도 체계에 종속시키지 않는다. 기존 수업 기록은 독립적으로 유지하고, 그 위에 자료실과 검색 색인을 추가한다.

현재 확인한 로컬 코드에서 수업 검색 대상은 제목·목표·활동, 단원 검색 대상은 제목이다. 단원 비고, 수업 참고사항·피드백·교재 등은 검색에서 빠져 있다. 현재 코드의 운영 저장 경로는 GitHub `data/planner.json`이고 파일 저장 한도는 900,000바이트다. Neon 연결 자체를 DB 이전 완료로 취급하지 않는다. 운영 DB 전환은 별도 구현·실제 저장 검증이 필요하다.

대표적인 개선 대상은 3학년 영어 「8단원 I'm happy.」 비고의 ‘우리 반 마음 통역소’ 초안이다. 제목을 기억하지 못해도 활동, 주제, 운영 조건, 미확정 사항으로 찾을 수 있어야 한다.

## 2. 핵심 준칙

1. **원본 하나, 여러 접근 경로:** 같은 기록을 교과별·주제별로 보기 위해 복제하지 않는다. 하나의 영속 ID에 여러 분류를 연결한다.
2. **교육과정과 운영 맥락을 구분:** 공식 성취기준·영역과 ‘카드 활동·15분·인쇄 필요’ 같은 실무 라벨을 별도 관리한다.
3. **기록부터, 정리는 나중에:** 분류가 부족해도 저장·검색할 수 있다. 미분류는 오류가 아니다.
4. **확인된 사실과 추천을 구분:** 자동 추론한 교과 연계·성취기준은 추천으로만 표시한다. 실제 적용·실시 사실을 생성하지 않는다.
5. **교과서 단원 번호는 보조 위치:** ‘8단원’은 출판사·판본·학년·학기와 함께 저장하고, 장기 검색의 대표 분류로 쓰지 않는다.
6. **날짜 없는 초안을 허용:** 기록 작성일과 실제 수업일을 분리한다. 미정인 실시일·학반·교시를 오늘이나 임의 값으로 채우지 않는다.
7. **재사용은 출처가 남는 새 작업:** 과거 원본은 보존하고 새 초안·수업은 독립 편집한다. 원본 변경을 새 수업에 자동 전파하지 않는다.
8. **라벨 이름이 바뀌어도 연결 보존:** 내부 ID는 유지하고 대표 명칭과 별칭만 바꾼다.
9. **검색은 교육적 적합성을 보증하지 않음:** 같은 주제라도 다른 교과의 목표·성취기준·평가는 다시 판단한다.
10. **정리는 지속적인 추가 업무가 되지 않음:** 화면은 익숙한 입력란을 유지하고 선택적 분류와 자동 추출을 뒤에 둔다.

## 3. 자료의 단위

| 자료 유형 | 보관 내용 | 날짜 필요 여부 | 기본 연결 |
|---|---|---|---|
| 기존 수업 기록 | 날짜별 계획, 준비, 실제 학급 반응 | 달력 등록 시 필요 | 기존 lesson ID 유지 |
| 단원 계획 | 단원 목표, 차시 구성, 비고 | 필요 없음 | 기존 unit ID 유지 |
| 날짜 없는 초안 | 공개수업 설계, 아이디어, 미완성 수업안 | 필요 없음 | 단원 연결 선택 |
| 활동 자료 | 발문, 활동 절차, 평가 도구 등 선택한 일부 | 필요 없음 | 추출한 원문과 버전 연결 |
| 참고 자료 | 파일, URL, 지도서 근거, 인용·요약 | 필요 없음 | 출처·첨부 대상 연결 |

모든 문장을 별도 자료로 쪼개지 않는다. 기존 수업·단원은 그 자체를 색인한다. 내용 일부를 반복해서 쓰고 싶을 때에만 ‘이 부분을 자료로 보관’을 사용한다. 장문의 비고에 있는 소제목은 검색 결과에서 해당 부분으로 바로 이동할 수 있게 색인한다.

자료실은 원본들의 통합 보기다. 달력에 나타나는 것은 실시일과 학반이 정해진 수업이며, 날짜 없는 초안은 자료실에만 나타난다. 같은 학반의 진도나 모든 차시의 공통 설계를 별도로 관리할 의무는 없다.

## 4. 교육과정 분류

### 4.1 범위와 구조

기본 탐색 경로는 ‘교육과정 판본 → 학교급 → 교과 → 학년군 → 해당 교과 영역 → 성취기준’이다. 실제 데이터는 이 경로 하나에 강제로 종속시키지 않고 다중 연결을 허용한다. 주제나 활동 방식으로 교과를 가로질러 찾는 경로도 제공한다.

초등 교과 사전의 초기 범위는 국어, 도덕, 사회, 수학, 과학, 실과, 체육, 음악, 미술, 영어, 바른 생활, 슬기로운 생활, 즐거운 생활이다. 교과별 적용 학년과 공식 영역은 선택한 교육과정 판본의 자료에서 가져온다. 모든 교과를 모든 학년에 동일하게 배치하지 않는다.

창의적 체험활동은 별도 교육활동 유형으로 지원한다. 학교자율시간은 교과 이름과 같은 층위에 섞지 않고 운영 구분으로 기록하며, 학교가 개설한 과목·활동을 추가로 연결할 수 있게 한다. ‘융합’은 교과를 대신하는 하나의 값이 아니라 주교과·연계교과와 연계 설명으로 표현한다.

### 4.2 저장할 항목

| 항목 | 규칙 |
|---|---|
| 교육과정 계열 | 2022 개정 등을 저장. 과거 기록의 판본을 날짜만 보고 소급 확정하지 않음 |
| 고시·문서 판본 | 고시번호, 발령·적용 정보, 원문 URL, 별책·쪽, 확인일을 별도 보관 |
| 학교급·학년군 | 초등 / 1~2·3~4·5~6학년군. 실제 실시 학년과 별도 |
| 실제 적용 학년 | 기존 기록의 1~6학년 값. 수업 실행의 사실 |
| 활용 가능 학년 | 교사가 지정한 범위. 실제 적용 학년에서 다른 학년으로 자동 확대하지 않음 |
| 주교과·연계교과 | 주교과 우선, 연계는 복수 가능. 추천 연계와 확인된 연계를 구분 |
| 교과 영역 | 교과·판본별 공식 영역 사전 참조. 교과 간 동일 이름이라고 자동 병합하지 않음 |
| 성취기준 연결 | 판본·학교급·교과·학년군·코드로 식별. 코드 문자열 하나만 전역 키로 사용하지 않음 |
| 연결 목적 | 주목표 / 보조 연계 / 재구성 후보 |
| 교과서 위치 | 출판사·저자·판본·학년·학기·단원·차시·쪽. 알 수 없는 값은 미정 |

‘내용 체계’의 핵심 아이디어 및 지식·이해, 과정·기능, 가치·태도는 상세 탐색·설계 보조 항목으로 지원한다. 매 수업마다 교사가 이 칸들을 전부 채우게 하지 않는다. 공식 문서에 명시된 연결은 사전에서 표시하고, 그 밖의 교사 해석은 별도 분석으로 기록한다. 성취기준의 문구를 기계적으로 세 부분으로 쪼개 공식 분류인 것처럼 저장하지 않는다.

### 4.3 성취기준 정확성

검증에는 두 축이 필요하다.

- **원문 검증:** 해당 코드·문구·판본이 공식 자료와 일치하는가? 상태는 미확인 / 원문 확인 / 구판.
- **수업 연결 판단:** 이 수업의 목표·학생 활동·평가 증거에 실제로 맞는가? 상태는 추천 / 교사 연결 / 재검토.

원문에서 확인된 기준도 그 수업에 적합하다는 뜻은 아니다. 지도서나 대화에서 전달받은 기준은 출처를 그렇게 표시한다. 이번 설계에서 기존 초안의 성취기준 원문을 재검증했다고 표기하지 않는다.

같은 교육과정 계열 안에서도 일부 개정이 있으므로 원문 판본을 고정한다. 새 판본이 들어와도 과거 수업의 연결을 자동 교체하지 않고 대응 관계와 재검토 안내를 둔다. 기준 사전은 NCIC·교육부·국가교육위원회의 고시와 원문을 우선하며, 판본이 식별되지 않는 재게시 자료는 검증 근거로 단독 사용하지 않는다.

## 5. 실무 라벨 사전

공식 교육과정 라벨과 달리 아래 라벨은 앱을 위한 교사 업무용 분류다.

| 축 | 대표값 예시 | 부여 기준 |
|---|---|---|
| 학습 주제·개념 | 감정·상태, 나이, 분수, 생태, 지역사회 | 배우는 내용이 실제 본문에 있는가 |
| 학생이 하는 일 | 비교하기, 분류하기, 질문하기, 설명하기, 검증하기, 표현하기 | 관찰 가능한 학습 행동인가 |
| 활동 방식 | 정보 차이, 역할 교대, 토의, 실험, 현장 관찰, 제작 | 수업 운영 절차에 실제 등장하는가 |
| 산출물·평가 자료 | 전달 카드, 관찰 기록, 주장 글, 발표, 수행 점검표 | 만들거나 수집할 결과물인가 |
| 운영 조건 | 소요 시간, 개인·짝·모둠, 공간, 준비물, 기기·인쇄 | 서술 또는 구조화된 값에서 확인되는가 |
| 지원 조건 | 그림 지원, 문장 틀, 따라 쓰기, 읽기 부담 낮음 | 구체적인 지원 방식이 있는가 |
| 사용 맥락 | 공개수업, 원어민 협력, 단원 정리, 보충 | 실제 목적 또는 명시된 의도인가 |

시간은 ‘5분·10분·15분’ 태그를 각각 만들기보다 숫자와 범위로 저장한다. 특히 전체 수업, 핵심 활동, 개별 활동의 소요 시간을 구분한다. 모둠 크기·교사 설명 시간·준비물도 가능한 한 전용 필드로 둔다.

라벨 운영 규칙:

- 한 축의 대표어는 하나로 정하고 별칭으로 검색을 돕는다. 예: ‘짝활동’은 ‘짝 활동’으로 통합한다.
- 의미가 비슷해도 같지 않으면 합치지 않는다. ‘감정’과 ‘공감’, ‘역할극’과 ‘역할 교대’는 별개의 개념일 수 있다.
- ‘감정↔마음’ 같은 확장은 검색 후보를 넓히는 관계로 취급하고 공식 교과 연계로 취급하지 않는다.
- 학년·교과·학반·날짜·교과서 위치는 이미 있는 필드로 검색하고 같은 내용을 태그로 중복 생성하지 않는다.
- 화면에는 핵심 라벨 3~5개를 먼저 보여주되 나머지 정보와 전체 검색은 유지한다.
- 자주 쓰는 개인 라벨은 허용하고, 동의어 후보가 보이면 기존 라벨을 먼저 추천한다. 정기적인 대량 라벨 정리 의무는 없다.
- AI가 제안한 라벨에는 근거 문장과 추천 표시를 둔다. 저장 전에 모든 추천을 확인해야 하는 절차는 만들지 않는다.

## 6. 상태와 기록 부담

기존 ‘계획 중·자료 준비 중·준비 완료·수업 완료’는 실제 수업의 진행 상태다. 자료의 ‘초안·사용 가능·보관’과 다르므로 별도 필드로 관리한다. 수업 완료는 좋은 수업이었다는 평가도, 자료가 완성됐다는 뜻도 아니다.

일반 수업은 현재 입력 방식 그대로 저장한다. 앱이 이미 아는 교과·학년·날짜·단원과 본문은 자동으로 검색에 반영한다. 새 자료를 독립 저장할 때 필요한 것은 제목, 자료 유형, 내용 또는 자료 위치이며, 나머지는 미분류로 두어도 된다. 제목도 본문 첫 줄을 임시 제목으로 제안할 수 있다.

선택적 ‘다시 쓸 때 참고’ 세 항목:

1. 실제로 효과가 있었던 부분.
2. 어려웠거나 다음에 바꿀 부분.
3. 준비·운영 조건.

수업 성찰 작성은 강제하지 않는다. 기존 피드백에 적은 내용은 그대로 검색한다. 빈 기록으로 효과·실시 여부를 추측하지 않는다. ‘추천’ 표시는 교사의 명시적인 즐겨찾기나 평가가 있을 때만 한다.

## 7. 검색과 열람

### 7.1 화면 구성

현재 테마를 유지하고 ‘자료실’ 메뉴를 추가한다. 첫 화면은 기존 오늘의 수업을 유지한다. 자료실에는 검색창, 필터, 검색 결과, 선택한 자료 미리보기를 둔다. 좁은 화면에서는 미리보기를 별도 패널로 연다.

- 검색창: 제목을 몰라도 단어·문장·성취기준 코드로 찾기.
- 기본 필터: 교과, 학년/학년군, 자료 유형, 초안 여부.
- 추가 필터: 교육과정 판본, 성취기준, 기간, 주제, 활동 방식, 소요 시간, 준비 조건, 즐겨찾기.
- 검색 결과: 제목, 교과·학년, 자료 유형·상태, 일치한 본문, 시간 범위, 준비 조건, 원본 위치.
- 미리보기: 전체 내용, 출처, 적용 맥락, 남은 점검사항, 활용 버튼.

학년군과 실제 학년은 다른 필터다. 날짜 없는 자료는 별도 ‘실시일 미정’으로 찾을 수 있다. 자료실의 기본 검색은 모든 연도·초안을 포함하며, 달력의 현재 달이나 현재 교과 필터를 몰래 물려받지 않는다. 수업 편집 중 자료를 찾을 때만 ‘현재 수업 기준’ 필터를 눈에 보이게 제안한다.

### 7.2 검색 범위

제목, 목표, 활동, 교재·준비물, 준비 체크 문구, 피드백, 참고사항, 단원 성취 수준·기본설계·비고·차시 내용, 독립 자료 본문, 출처·라벨, 허용된 첨부파일 추출문을 포함한다. 외부 URL은 링크를 저장했다고 본문까지 검색되는 것으로 표시하지 않는다. 파일 본문 추출은 완료·대기·실패·미지원 상태를 구분한다.

긴 비고는 원본을 유지하면서 소제목과 문단 단위로 검색한다. 결과는 자료 단위로 묶어 중복 노출을 줄이고, 가장 관련 있는 부분을 펼친다. 검색 결과에서 발견된 ‘미확정’ 조건도 함께 보여준다.

### 7.3 검색 규칙

- 같은 축에서 선택한 여러 값은 기본 OR, 서로 다른 축은 AND다.
- 정확한 코드·제목 일치를 우선하고, 확인된 라벨·본문 일치 순으로 찾는다. 최신성은 보조 기준이며 오래된 관련 자료를 밀어내지 않는다.
- ‘나이’가 본문에만 있어도 찾을 수 있어야 한다. 라벨이 없는 자료를 검색에서 제외하지 않는다.
- 공식 성취기준 필터의 기본 결과는 교사가 연결한 자료다. 자동 추천까지 포함할지는 별도 선택한다.
- 결과가 없으면 어떤 필터를 완화할지 제안하며 조건을 몰래 바꾸지 않는다.
- 자주 쓰는 조건은 ‘저장한 검색’으로 보관한다. ‘3~4학년·인쇄 없이·15분 이하’ 같은 가상 책장이며 자료 복제나 이동이 아니다.

자연어 검색 예: ‘3학년이 짝과 말하고 카드를 만드는 20분 안팎 활동’. 확인 가능한 조건을 필터 칩으로 보여주고, 아직 해석하지 못한 말은 본문 검색어로 남긴다. 실제로 없는 시간이나 준비 조건을 AI가 채워 넣지 않는다.

## 8. 재현·수정·첨부

| 행동 | 결과 | 보존 원칙 |
|---|---|---|
| 원본 보기 | 당시 내용과 운영 맥락 열람 | 변경 없음 |
| 참고로 연결 | 현재 수업에 자료 링크와 짧은 설명 추가 | 원문은 그대로; 참조 버전 기록 |
| 일부 가져오기 | 선택한 활동·발문·평가 기준을 새 블록으로 추가 | 대상 기존 내용 뒤에 추가; 덮어쓰기는 별도 선택 |
| 새 수업으로 재구성 | 독립 초안 생성 후 필요할 때 달력 등록 | 새 ID; 원본 ID·버전·가져온 범위 보존 |

‘일부 가져오기’는 대상 수업과 넣을 위치를 선택하고 반영 내용을 미리 보여준다. 첨부할 자료가 같은 원본·버전·범위로 이미 연결되어 있으면 중복 여부를 알린다. 가져온 블록을 수정해도 원본은 바뀌지 않는다. 잘못 가져온 경우 그 작업을 취소할 수 있도록 변경 이력을 둔다.

새 수업에는 목표·활동·자료를 선택적으로 복사한다. 실제 실시일, 학반, 학생 반응, 완료 상태, 준비 완료 체크는 과거 실적을 새 수업의 실적으로 복사하지 않는다. 과거 피드백은 필요하면 ‘이전 적용 시 참고’로 별도 연결한다. 날짜·학반을 정하기 전에는 자료실 초안으로 두고, 달력에 넣을 때만 입력한다.

원본이 수정되면 ‘새 버전 있음’을 표시할 수 있지만 이미 작성한 수업을 자동 변경하지 않는다. 당시 참고했던 버전을 다시 열 수 있어야 재현이 가능하다. 원본과 새 계획의 변경 내용은 비교할 수 있게 한다.

교과를 바꾸어 재사용할 때는 목표 → 학생이 할 일 → 결과물 → 평가 증거의 연결을 다시 확인한다. 예를 들어 영어 카드 활동의 운영 방식은 국어 수업에 활용할 수 있지만 영어 성취기준과 평가는 그대로 넘기지 않는다. 해당 교과 성취기준은 미연결 또는 추천 상태에서 시작한다.

## 9. 실제 기록에 적용한 예시 — 마음 통역소

이 표는 라벨링 시연이며 운영 데이터에 새 라벨을 저장한 결과가 아니다.

| 항목 | 분류 예시 |
|---|---|
| 원본 | 3학년 영어 「8단원 I'm happy.」의 비고 |
| 자료 유형·상태 | 공개수업 초안 / 수정 중 |
| 대상 | 실제 구상 3학년 / 교육과정 연결 학년군 3~4학년 |
| 실시일·반·교시 | 미정 |
| 주교과 | 영어 |
| 교육과정 연결 | 인계된 2022 개정 관련 기준; 원문 검증 여부 별도 표시 |
| 주제 | 감정·상태, 나이, 교실 생활 |
| 행동·방식 | 듣고 확인하기, 표현하기, 정보 차이, 역할 교대, 카드 제작 |
| 지원 | 그림, 낱말 보기, 문장 틀 |
| 시간 | 핵심 활동 30분 / 상담소 활동 16분 / 전체 공개수업 시간 미정 |
| 산출물 | 이모티콘 카드 5장, 마음 전달 카드 1장 |
| 준비 조건 | 사전 재단 카드, 윤곽, 낱말 붙임표 |
| 미확정 | 모둠 인원 배치, 4분 회차 운영 가능성, 동선 등 |
| 적용 경험 | 실제 실시 확인 없음; 효과가 검증된 수업으로 표시하지 않음 |

찾는 방법:
- ‘마음 통역소’ → 단원 비고의 초안 제목·본문 일치.
- ‘영어 + 3학년 + 카드 제작’ → 분류와 활동 라벨 조합.
- ‘그림 도움으로 말하기’ → 지원 조건과 본문 검색, 필요 시 유사 표현 확장.
- ‘재방문 검수’ → 라벨에 없는 상세 운영 절차도 본문에서 발견.

현재 수업에 ‘상담소 16분’ 부분만 가져올 경우 그 절차, 필요한 자료, 모둠 운영의 미확정 주의사항을 함께 선택할 수 있게 한다. 네 단계 전체를 자동으로 합쳐 넣거나 불확실한 모둠 운영을 확정안으로 바꾸지 않는다. 전체 공개수업 시간이 30분이라고 표시하지 않는다.

## 10. 구현용 데이터 구조와 검색 기반

기존 lesson/unit의 ID와 기록 형식은 가능한 한 유지하며 추가 테이블로 확장한다.

| 구성 | 핵심 역할 |
|---|---|
| 자료 항목 | 기존 수업·단원의 참조 또는 독립 초안·자료의 원본; 제목·유형·작성/수정일 |
| 자료 버전 | 재현 가능한 본문 스냅샷, 버전 ID, 변경 설명 |
| 교육과정 문서·성취기준 사전 | 판본별 공식 원문·코드·영역·출처 |
| 교육과정 연결 | 자료와 기준의 다대다 연결, 목적, 원문 검증과 연결 판단 |
| 라벨·별칭·연결 | 축별 대표어, 동의어, 추천/확정, 근거 |
| 자료 관계 | 참고함·부분 추출·재구성함·첨부함; 원본 버전과 범위 |
| 첨부 자료 | 파일 위치, 형식, 크기, 해시, 출처, 접근권한, 본문 추출 상태 |
| 검색 색인 | 원본에서 재생성 가능한 문서·구간별 검색 데이터 |

자료 관계는 `원본 ID + 원본 버전 ID + 선택 범위/블록 ID + 대상 ID + 적용 시각`을 보존한다. 줄 번호만으로 참조하지 않는다. 아직 블록 ID가 없는 긴 비고는 해당 버전과 선택 문자열/해시를 함께 보관한다.

원본 데이터와 검색 색인은 분리한다. 색인 오류가 원본 소실을 뜻하지 않도록 언제든 재생성할 수 있어야 한다. 저장 성공과 색인 대기·실패를 구분하고, 갱신이 늦으면 이를 표시한다. 삭제·보관·권한 변경도 색인에 반영한다.

초기 검색 구현은 PostgreSQL의 구조화 필터와 한국어 부분 일치 검색을 우선한다. Unicode 정규화, 공백·영문 대소문자·아포스트로피 차이를 검색용 데이터에서 처리하되 원문은 바꾸지 않는다. `pg_trgm` 등의 확장은 실제 DB 제공 여부를 확인한 뒤 사용하며 짧은 검색어의 보완 경로도 둔다. 기본 영문 전문검색 설정만으로 한국어 검색 품질을 확보했다고 간주하지 않는다.

자료가 늘면 서버에서 조건을 적용하고 결과를 페이지 단위로 내려준다. 전체 데이터를 매번 브라우저로 보내 검색하지 않는다. 필터용 인덱스와 본문 검색용 인덱스를 나누며, 수정한 자료만 갱신한다. 의미 검색은 정확 검색을 대체하지 않고 보조 결과로 추가한다. 검색 이유·원문 위치를 항상 보여준다.

파일 본문은 적절한 추출기/OCR 지원 범위부터 단계적으로 색인한다. PDF·HWP·이미지를 모두 즉시 검색 가능하다고 약속하지 않는다. 큰 첨부파일은 DB 본문에 넣지 않고 접근권한이 적용된 파일 저장소에 보관한다. DB에는 메타데이터와 검색 가능한 추출문을 둔다.

향후 Codex 자연어 입력도 같은 인증·검증·버전 충돌 검사 경로를 사용한다. 앱만 DB를 쓰고 Codex가 과거 GitHub 파일을 계속 고치는 이중 저장 구조를 남기지 않는다.

## 11. 기존 기록 정리와 구현 순서

### 단계 1 — 기존 자료가 검색에서 빠지지 않게 하기

- 모든 기존 수업·단원 필드의 본문 검색.
- 기존 ID·작성일·단원 연결·실시 기록 보존.
- 비고 속 초안도 원본 위치와 함께 표시.
- 날짜 없는 독립 초안의 저장 구조 설계·추가.
- 현재 교과·학년 등 확실한 값만 자동 분류. 불명확한 성취기준·판본·활동 방식은 미분류 또는 추천.

### 단계 2 — 축적 가능한 저장 기반과 자료실

- 중단된 DB 전환 작업의 실제 상태부터 확인하고 별도로 마무리.
- 원본 백업, 레코드/내용 대조, 동시 저장 충돌 검증 후 전환.
- 구조화 필터, 페이지 조회, 검색 색인, 자료실 메뉴, 부분 가져오기.
- 자료와 메타데이터·버전·첨부 목록을 함께 내보내고 복원 검증.

단계 1의 제한적인 검색 보완은 현 저장소에서도 가능하지만, 대규모 라벨과 파일·버전 축적을 900KB 단일 파일에 얹지 않는다.

### 단계 3 — 교육과정과 교과 확장

- 모든 초등 교과가 들어갈 공통 구조를 먼저 만들고 검증된 사전을 순차 확충.
- 현재 많이 쓰는 영어를 먼저 연결하되 교과 필드를 영어에 고정하지 않음.
- 기존 사용자 기록의 기준은 출처를 보존하고 공식 원문 대조를 별도로 수행.
- 저장한 검색, 라벨 별칭, 버전 비교, 선택적 운영 메모 제공.

### 단계 4 — 필요할 때 검색 고도화

- 자연어 조건 해석, 의미 검색, 첨부 본문 검색 확대.
- 실제로 못 찾은 검색어를 기준으로 품질 개선.
- 라벨 추천을 위해 외부 AI 서비스를 도입할 경우 비용과 전송 범위를 먼저 구체화.

## 12. 완성 여부를 판단할 검증 사례

1. ‘마음 통역소’ 검색으로 제목이 다른 기존 단원의 비고 초안을 찾는다.
2. 라벨이 하나도 없는 자료도 본문 검색으로 찾는다.
3. 날짜 없는 초안이 저장되고 달력에는 나타나지 않는다.
4. 같은 자료가 교과·주제·저장한 검색에 동시에 나타나도 원본은 하나다.
5. 여러 학년군·교과에 연결할 수 있으나 추천 연결과 확인된 연결이 섞이지 않는다.
6. 과거 교육과정과 2022 개정의 동일 표기 코드가 충돌하지 않는다.
7. 성취기준 원문 일치와 수업 적합성 판단을 각각 확인할 수 있다.
8. ‘상담소 16분’만 가져오면 대상 수업의 기존 활동은 보존되고 출처와 미확정 조건이 남는다.
9. 새 수업에 과거 실시일·학반·완료 체크·학생피드백이 새 실적으로 복사되지 않는다.
10. 원본을 수정해도 이미 가져온 계획은 바뀌지 않고 참조 당시 버전을 다시 열 수 있다.
11. 한 자료 수정 후 색인 실패가 나도 원본은 저장되어 있고 재색인으로 복구할 수 있다.
12. 파일 추출 실패·외부 링크만 저장한 상태가 본문 검색 가능으로 잘못 표시되지 않는다.
13. 한국어 띄어쓰기 변형, 짧은 검색어, 영문 아포스트로피, 정확한 성취기준 코드의 검색 품질을 확인한다.
14. 자료 1만·10만 건의 모의 데이터에서 검색·필터·다음 페이지·변경 반영을 측정한다. 결과 20개 조회가 전체 레코드 다운로드를 요구하지 않아야 한다. 초기 목표는 일반 검색의 95%가 2초 이내이며 실측과 DB 요금제에 따라 조정한다.
15. 내보낸 원본·분류·출처·버전을 복원한 뒤 동일한 자료를 검색하고 재사용할 수 있다.

## 1차 구현 범위 (2026-11-04 KST)

구현: 기존 수업·단원 전체 본문 색인, PostgreSQL 페이지 검색, 전 교과/학년군/라벨 필터, 날짜 없는 자료, 선택 분류, 저장한 검색, 출처 버전이 남는 참고·부분 추가·독립 초안/수업 재구성. 저장과 검색 문서를 같은 트랜잭션으로 갱신하여 색인만 실패하는 상태를 방지합니다. 기존 학년·교과 외의 교육과정 연결은 임의 추정하지 않습니다.

후속 범위: 공식 교육과정 사전 수집·검증, 정규 라벨 ID 및 별칭 관리 화면, 교과서 위치 전용 필드, 단원과 독립 초안의 전용 관계 편집, 자동 라벨 추천/의미 검색, 첨부 파일 업로드/OCR, 전체 자료·버전의 앱 내 가져오기/복원, 1만·10만 건 부하 측정. 현재 공식 기준과 교과서 위치는 분류 출처/본문에 직접 기록할 수 있습니다. 선택 자료 JSON과 계획 JSON 내려받기는 제공하지만 전체 DB 백업을 대체하지 않습니다.

자료실은 20개씩 DB 검색하며 독립 자료의 전체 본문을 처음부터 내려받지 않습니다. 달력과 오늘 화면의 기존 전체 수업 모델은 유지하여, 대규모 과거 수업까지 누적되면 별도의 기간 조회 최적화가 필요합니다. 설계 목표인 모든 항목과 성능 수치를 1차 배포에서 검증 완료했다고 해석하지 않습니다.

# 수업 데이터 규칙

운영 파일은 `data/planner.json`입니다. 루트 구조는 `{ "schemaVersion": 1, "lessons": [], "units": [] }`이며 선택적으로 `timetable` 배열을 추가할 수 있습니다. 정확한 검증 규칙은 `lib/planner.ts`에 있습니다. 검증 명령은 `npm run validate:data`입니다.

## 수업 (`lessons`)

| 키                | 의미                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| `id`              | UUID. 수정할 때 보존                                                                             |
| `subject`         | 교과명. 사용자 지정 교과도 가능                                                                  |
| `date`            | 한국 날짜, `YYYY-MM-DD`. 필수                                                                    |
| `period`          | 선택 항목. 1~12교시. 생략하면 교시 미지정                                                        |
| `timetableOrigin` | 선택 항목. `{ slotId: UUID, date: 원래 등록 날짜 }`. 수업 이동·편집 시 보존                      |
| `title`           | 수업제목. 필수                                                                                   |
| `grade`           | 1~6 사이의 정수                                                                                  |
| `classroom`       | 반을 나타내는 문자열. 예: `"2"`. 화면에서 ‘반’을 붙임                                            |
| `status`          | `계획 중`, `자료 준비 중`, `준비 완료`, `수업 완료` 중 하나                                      |
| `objective`       | 학습목표                                                                                         |
| `materials`       | 교재·쪽수·준비물·참고 링크를 자유롭게 작성                                                       |
| `preparation`     | 선택 항목. `{ id: UUID, text: 문자열, done: boolean }` 배열, 최대 100개. 기존 기록에서 생략 가능 |
| `activities`      | 활동 내용                                                                                        |
| `feedback`        | 학생들이 수업에 보인 반응과 다음 수업에 참고할 점                                                |
| `notes`           | 참고사항                                                                                         |
| `unitId`          | 단원 UUID 또는 `null`                                                                            |
| `sessionId`       | 해당 단원 차시의 UUID 또는 `null`                                                                |
| `createdAt`       | 최초 작성 시각. ISO 8601 UTC 문자열, 수정 시 보존                                                |
| `updatedAt`       | 마지막 변경 시각. ISO 8601 UTC 문자열                                                            |

남은 일 수는 `Asia/Seoul`의 오늘을 기준으로 화면에서 계산하며 데이터에 저장하지 않습니다. 빈 선택 항목은 `null`, 빈 서술 항목은 `""`를 사용합니다. HTML을 해석하지 않고 일반 텍스트로 표시합니다.

준비 체크는 수업 상태와 독립적이며, 모든 체크를 완료해도 상태를 자동 변경하지 않습니다. 수업 복제 시 항목마다 새 UUID를 부여하고 `done`을 `false`로 초기화합니다. 오늘 화면의 빠른 기록은 기존 `feedback`을 보존하고 빈 줄 뒤에 추가합니다. 지난 수업은 전체 데이터 중 같은 학년·반·교과이고 날짜가 더 이른 가장 최근 수업입니다. 같은 날 수업은 교시 정보가 없으므로 지난 수업으로 선택하지 않습니다.

## 기초시간표 (`timetable`)

선택 배열이며 기존 파일에서 생략 가능합니다. 최대 300개 항목을 저장합니다. 각 항목은 `id`, `weekday`(월=1~금=5), `period`(1~12), `grade`, `classroom`, `subject`, `title`(빈 문자열 허용), `startDate`, `endDate`(무기한은 null)를 가집니다. 같은 요일·교시의 적용 기간은 서로 겹칠 수 없습니다. 시간표가 바뀔 때는 기존 항목의 종료일과 새 항목의 시작일을 지정할 수 있습니다.

주별 생성은 월~금의 실제 날짜 중 각 항목의 적용 기간에 포함되는 수업만 대상으로 합니다. 선택한 항목 전체를 한 번의 SHA 검사·저장으로 반영합니다. 기존 수업 중 같은 `timetableOrigin.slotId`와 `timetableOrigin.date`가 있으면 이동한 수업도 중복으로 등록하지 않습니다. 현재 날짜·교시가 겹치는 수업도 제외합니다. 교시가 없는 같은 학반·교과 수업과 대상 학년 행사는 확인 안내를 표시하고 기본 선택을 해제합니다.

생성 시 목표·활동·피드백은 비우고 상태는 `계획 중`으로 설정합니다. 제목은 시간표 제목 또는 ‘교과명 수업’을 사용합니다. 등록 이후 실제 수업은 독립적입니다. 시간표 항목의 변경·삭제는 기존 수업을 바꾸지 않습니다. 다른 학반으로 수업 복제 시 `timetableOrigin`은 제거합니다. Codex로 날짜를 바꾸더라도 원래 연결 정보는 보존합니다. 수업 삭제 후에는 명시적인 주별 등록으로 다시 만들 수 있습니다.

학교 정보는 공개 설정 파일 `data/school.json`에 있으며, 나이스 행사 캐시는 수업 데이터 파일에 넣지 않습니다. 학교정보 API에서 확인한 오션초등학교(부산광역시북부교육지원청)의 코드는 `C10 / 7201223`입니다.

## 단원 (`units`)

`id`, `title`(단원명), `grade`, `subject`, `achievement`(성취 수준), `design`(기본설계), `notes`(비고), `sessions`, `createdAt`, `updatedAt`을 가집니다.

`sessions`는 `{ "id": "차시 UUID", "activity": "활동내용" }` 배열입니다. 배열 순서가 1차시, 2차시…입니다. 기본 6개, 1~100개까지 가능하며 차시를 재배열해도 UUID를 보존합니다. 연결된 수업이 있는 차시는 수업의 연결을 먼저 해제해야 삭제할 수 있습니다.

성취 수준은 선생님이 직접 정한 내용만 기록합니다. `design`은 선생님이 명시적으로 요청한 경우에만 채우며 그 외에는 빈칸을 유지합니다.

## 자연어 수정 원칙

1. 수정 전에 최신 원격 데이터를 확인합니다. 수정 대상은 교과·날짜·학년·학반·제목으로 식별합니다. 여러 후보가 있으면 묻습니다.
2. 상대 날짜는 한국 시간 기준 실제 날짜로 해석합니다. 날짜·학급 등 필수 정보가 없고 맥락에서도 결정할 수 없다면 사용자에게 확인합니다.
3. UUID와 `createdAt`을 유지하고, 요청한 필드와 `updatedAt`만 변경합니다. 새 항목만 새로운 UUID와 작성 시각을 부여합니다.
4. 단원과 수업은 같은 학년·교과여야 합니다. 다른 학반으로 복제할 때 새 UUID를 부여하고 피드백을 비우며 상태를 `계획 중`으로 설정합니다. 날짜와 대상 학반을 확인합니다.
5. 피드백, 목표, 성취 수준을 임의로 지어내거나 기존 내용을 덮어쓰지 않습니다. 실제 학생 이름을 새로 추가하지 않습니다.
6. 단원 삭제 시 수업은 보존하고 `unitId`·`sessionId`만 `null`로 바꿉니다. 삭제 전에 사용자가 단원 삭제를 요청했는지 확인합니다.
7. `npm run validate:data`를 실행합니다. 데이터만 바꾸는 경우 앱 코드는 수정할 필요가 없습니다.
8. 사용자 요청에 따라 원격 데이터 브랜치에 커밋을 반영해야 사이트에서 보입니다. 다른 쓰기가 발생해 push가 거절되면 강제 push하지 말고 최신 변경과 조정합니다. 같은 항목을 서로 다르게 수정한 경우에는 확인합니다.

## 저장 충돌

웹 API는 읽을 때의 파일 SHA를 GitHub Contents API에 전달합니다. 이후 다른 커밋이 같은 파일을 바꾸면 저장을 거절하며 최신 내용을 덮어쓰지 않습니다. 전체 파일 단위 충돌이므로 서로 다른 수업을 수정해도 충돌 안내가 나올 수 있습니다. 첫 버전은 자동 병합을 제공하지 않습니다.

## 노션 이전 규칙 (2026-10-16 확정)

- 사용자가 확정한 `전달됨`은 앞으로 `수업 완료`로 해석합니다. `계획된`은 `계획 중`, `수정 필요`는 원문을 참고사항에 남기고 `자료 준비 중`으로 옮겼습니다.
- 노션 수업 35개 기록을 원본에 기재된 학반별 수업 71개로 분리하고 단원 4개를 이전했습니다. 이는 새 학반으로 수업을 복제하는 기능과 달리 원래 공동 대상의 실제 기록을 옮긴 것입니다. 공동 피드백에는 원본 대상 학반을 표시했습니다.
- 단원 기본설계와 성취 수준은 사용자가 제공한 원문입니다. 단원은 학년·단원번호로 연결했고, 차시별 활동 차이로 차시 연결은 비워두었습니다.
- 원본 날짜가 있는 기록은 한국시간 자정으로 저장하고 시각 미제공 사실을 참고사항에 명시했습니다. 날짜가 없는 기록의 작성 시각은 이전 시각입니다.
- 원본 Markdown·CSV·PDF와 검증 해시, 변환 출처는 `data/notion-import-2026-10-16/`에 보관합니다. 해당 디렉터리는 이전 기록 보관용이며 앱이 읽고 쓰는 운영 데이터는 계속 `data/planner.json`입니다. PDF는 현재 앱의 첨부파일 화면에서 열 수 없으며 저장소의 보관본으로 확인할 수 있습니다.
